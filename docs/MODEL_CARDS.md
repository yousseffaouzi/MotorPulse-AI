# MotorPulse AI — Baseline model cards

MotorPulse AI is a local-first, software-only synthetic research lab. These cards document the two implemented decision baselines that can label or score simulated motor-condition windows: the fixed illustrative rule baseline and the healthy-trained anomaly baseline. They are not industrial diagnostic products, do not estimate physical failure probability, and are not validated for maintenance decisions on real machinery.

The cards describe implemented behavior and its evidence boundary. Dataset integrity checks, hashes and deterministic replay improve reproducibility; they do not establish physical validity, source authenticity, legal reuse rights or safety fitness.

## Card 1 — Illustrative rule baseline

**Implementation:** `motorpulse/sim.py::classify` plus sensor-quality gating in `MotorSimulator.sample_asset`.

**Baseline type:** fixed deterministic thresholds. This baseline is **not trained** and has no learned parameters.

### Source data

The rules operate on MotorPulse synthetic telemetry generated by the simulator. They do not fit a dataset and do not ingest NASA IMS or any other external dataset. Synthetic scenario labels are generator truth used for software evaluation, not observations of physical damage.

The current signal model uses 1024 Hz, 1024-sample synthetic vibration windows plus synthetic temperature and RPM. See [MODEL_ASSUMPTIONS.md](MODEL_ASSUMPTIONS.md) for generator assumptions and [DATASET.md](DATASET.md) for exported synthetic records.

### Intended use

- Provide a transparent deterministic reference for simulator demonstrations, API/dashboard behavior and regression tests.
- Supply a simple comparison baseline for the frozen anomaly detector on the same eligible synthetic windows in MP-011 and MP-037.
- Make threshold behavior easy to inspect and reproduce during software research.

It is not intended for real-machine protection, maintenance scheduling, safety interlocks, shutdown logic, fault confirmation or public-network control.

### Inputs and outputs

For a good synthetic sensor window, the rule baseline consumes only:

- `rms_g`
- `temperature_c`
- `crest_factor`

The current fixed conditions are:

- add an elevated-vibration reason when `rms_g >= 0.36`;
- add a high-temperature reason when `temperature_c >= 82.0`;
- add an impulsive-waveform reason when `crest_factor >= 2.7` **and** `rms_g >= 0.20`;
- when at least one reason is present, classify `critical` if `rms_g >= 0.55` **or** `temperature_c >= 92.0`;
- otherwise classify `warning`; with no reason, classify `normal`.

Sensor quality gates the machine assessment before those thresholds are applied. A `sensor_quality="missing"` event yields `health="unavailable"`, and a `sensor_quality="outlier"` event yields `health="suspect"`; neither is treated as a healthy negative observation.

Outputs are a categorical `health` value plus transparent `reasons`. The output is not a probability, confidence score, fault-type classifier or estimate of remaining life.

### Validation evidence

- Unit and API regression tests exercise threshold boundaries, reproducible simulation, sensor missing/outlier suppression, telemetry schema and controller behavior.
- MP-011 evaluates the unchanged rule output on the same eligible held-out synthetic windows used for anomaly-model evaluation, reporting confusion metrics and false alarms per synthetic negative-window hour where denominators exist.
- MP-037 rechecks rule predicates from source event values and explains same-window rule-versus-anomaly disagreements.

This evidence is synthetic and software-focused. It does not constitute independent physical validation, an ISO/OEM alarm study or measured field reliability.

### Failure modes

- **False positives from simulated operating conditions:** load, temperature, speed variation, drift or other generator effects can cross a fixed threshold without synthetic machine-fault truth.
- **False negatives below thresholds:** a scripted fault can be active while all fixed rule predicates remain below their alert boundaries.
- **Threshold brittleness:** behavior changes abruptly at fixed numeric boundaries and does not adapt to an asset's baseline, operating regime or uncertainty.
- **Sensor abstention:** missing and injected outlier windows suppress normal rule assessment, so alerts can be delayed or absent while data quality is poor.
- **Shared-generator bias:** the rules and the synthetic benchmark are authored within the same demonstration environment; good synthetic metrics would not prove domain transfer.
- **No fault discrimination:** reasons identify threshold predicates, not verified bearing, alignment, imbalance or overload causes.

### Limitations and prohibited claims

Do not describe the rule baseline as trained AI, calibrated condition severity, physical failure probability, a validated alarm limit, an ISO 20816 threshold, a safety function, a real fault diagnosis, maintenance lead time or remaining useful life. A rule warning/critical state is only a synthetic-lab decision for the current event.

## Card 2 — Healthy-trained anomaly baseline

**Implementation:** `motorpulse/anomaly.py`, with train-only preprocessing from `motorpulse/feature_pipeline.py` and portable source-verified artifacts from MP-035.

**Model version:** `1.0.0`.

**Method:** standardized Euclidean distance from a healthy synthetic training center (`healthy_training_zscore_euclidean`), with higher score meaning more unusual relative to that training baseline.

### Source data

Training accepts only MotorPulse synthetic feature-event runs in an MP-030 `whole_run_grouped` split with verified source manifests and MP-032 dataset cards. All planned train/validation/test source groups must be supplied for provenance checking, but fitting reads feature values only from training groups.

Within the training partition, parameter fitting uses only events whose synthetic effective scenario is `healthy` and whose `sensor_quality="good"`. At least eight eligible healthy windows are required. IMS data and unknown real-data labels are refused by this baseline.

### Intended use

- Provide a transparent, reproducible synthetic anomaly-detection baseline for research comparisons with the fixed rules.
- Demonstrate leakage-resistant training, frozen preprocessing, portable model artifacts and held-out synthetic evaluation.
- Surface unusual multivariate windows relative to the learned healthy synthetic center.

It is not intended to estimate physical fault probability, classify fault mechanisms, authorize maintenance, control equipment, replace inspection or transfer directly to real machinery.

### Inputs and outputs

The ordered numeric feature vector is fixed to exactly five fields:

1. `rms_g`
2. `crest_factor`
3. `band_80_400_rms_g`
4. `temperature_c`
5. `rpm`

Fault truth, configured severity, rule health/reasons, sensor-quality labels, identity and timestamps are excluded from the model vector. Preprocessing centers and scales are fitted on eligible training windows only; validation/test measurements never update them.

For each scorable window, the model returns a nonnegative anomaly score. The decision threshold is the **training-only empirical 99th percentile** of healthy training scores, and the implemented alert comparison is strictly `score > threshold`. This in-sample choice is not a guaranteed 1% held-out or field false-positive rate.

Events with missing or outlier sensor quality are unscorable and receive no anomaly score. A larger score means farther from the learned synthetic healthy center; it is not a failure probability.

### Validation evidence

- MP-010 regression tests verify training-only access, deterministic replay, feature exclusion, sensor gating, split/source integrity and no-overwrite behavior.
- MP-011 evaluates the frozen model on complete held-out MP-030 validation or test source groups and reports confusion counts, precision/recall/F1/specificity/FPR where defined, score-ranked average precision, false alarms per synthetic negative-window hour, and synthetic onset-to-first-alert delay.
- MP-034 verifies that preprocessing is fitted only on training data and remains frozen for held-out scoring.
- MP-035 saves/loads a strict JSON artifact tied to feature, split, dataset-card and source hashes; artifact integrity is reproducibility evidence, not scientific validity.
- MP-036 describes robustness slices across scripted operating regimes and sensor conditions without refitting the model.
- MP-037 compares frozen rules and anomaly decisions on the same held-out events and exposes representative disagreement examples.
- MP-038 researches a separate validation-only operating-point selection while preserving the original MP-010 model and untouched test evaluation; it is not a new model family.

All of that evidence remains synthetic. No field dataset has established accuracy, calibration, uncertainty, transfer reliability or maintenance benefit.

### Failure modes

- **Operating-regime novelty:** speed, load or temperature changes can increase distance even when synthetic machine truth is healthy, creating false positives.
- **Unmodeled faults or weak departures:** a fault can remain near the learned healthy center and be missed; the model is not a fault-type classifier.
- **Shared-generator bias:** train and held-out runs use the same simulator equations and feature construction, so seeded run separation does not establish real-domain generalization.
- **Threshold sensitivity:** the original 99th-percentile cutoff is estimated from the training score distribution and can be poorly matched to a different operating mix.
- **Sensor abstention:** missing/outlier windows are deliberately unscorable; prolonged poor data quality can hide or delay anomaly decisions.
- **Diagonal-distance assumption:** the score standardizes features independently and does not model covariance, nonlinear dynamics, causal mechanisms or calibrated uncertainty.
- **Feature-contract mismatch:** different sampling, units, preprocessing, source files or split provenance are rejected by verification tooling rather than silently scored.
- **Dataset shift:** real sensors, mounting, noise spectra, bearing geometry, duty cycles and failure mechanisms are outside the learned synthetic distribution.

### Limitations and prohibited claims

Do not call the anomaly score a probability of failure, calibrated health index, certified alarm, fault diagnosis, proof of generalization, maintenance recommendation, survival estimate or remaining useful life. Held-out synthetic precision/recall or detection delay must not be reported as field performance. Artifact SHA-256 values are integrity fingerprints, not signatures or validation certificates.

## RUL status — explicitly no model

**No RUL model exists in MotorPulse AI.** MP-039 is a **metadata-only** Remaining Useful Life research protocol and auditor. It produces **no predictions**, sets `provides_rul_estimates=false` and `allows_rul_model_training=false`, and requires independently reviewed terminal-failure/censoring evidence before any future prognostic work could even be authorized.

Synthetic fault onset, severity ramps, anomaly alerts, rule alerts, detection delay and the end of a simulation file are not terminal failure times. See [RUL_RESEARCH.md](RUL_RESEARCH.md) for the blocked-by-default protocol and preregistered evidence requirements.
